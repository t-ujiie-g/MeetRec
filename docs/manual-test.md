# 実機テスト手順（チェックリスト）

MeetRec は開発環境（Linux）で画面収録を実行できないため、ここにある項目はすべて人が実機で確認します。
macOS と Windows のそれぞれで、Zoom と Teams の両方について実施してください。

**うまくいかない項目があったら**：その状態のままメニューの「診断ログを保存」を実行し、
出力されたファイル（`diagnostics/MeetRec-diagnostics-*.txt`）と、どの項目で何が起きたかを報告してください。
診断ログには会議アプリのプロセス・ウィンドウ・マイク使用状況と、直近の動作ログが入っています
（会議アプリ以外のウィンドウ名は記録しません）。

記録用テンプレート：

```
OS / 機種：            （例：macOS 15.1 / MacBook Air M2、Windows 11 23H2 / ThinkPad X1）
MeetRec のビルド：     （CI の実行番号かコミット）
Zoom / Teams の版：
UI 言語：
```

## 0. 準備

- [ ] 会議の相手役（別の PC・スマホ、または同僚）を用意する。1 人で行う場合はスマホから同じ会議に参加し、スマホで音声を流す。
- [ ] 音楽など「会議以外の音」を出せるアプリ（ブラウザで動画など）を用意する。
- [ ] 以前のテストの設定を消して初回状態にする。
  - macOS：`~/Library/Application Support/MeetRec` を削除
  - Windows：`%APPDATA%\MeetRec` を削除

## 1. インストールと初回起動

- [ ] README の手順でインストールし、起動できる。
  - Windows：`MeetRec-setup.exe` で入り、スタートメニューに MeetRec が出る。もう一度実行すると（MeetRec が動いたままでも）
    入れ替えられる。設定 → アプリ から削除でき、削除後はログイン時に起動しない。
- [ ] メニューバー / 通知領域にアイコンが出る。Dock / タスクバーにはウィンドウが出ない。
- [ ] （macOS）画面収録とマイクの権限の案内が出る。「設定を開く」で該当の設定画面が開く。許可して MeetRec を再起動する。
- [ ] メニューを開くと「待機中」と表示され、全項目が日本語で読める。
- [ ] 「ログイン時に起動」にチェックが付いている。
  - macOS：システム設定 → 一般 → ログイン項目 に MeetRec がある
  - Windows：タスク マネージャー → スタートアップ アプリ に MeetRec がある
- [ ] PC を再起動（またはログアウト → ログイン）すると MeetRec が自動で起動する。
- [ ] MeetRec をもう一度起動しても二重に常駐しない。

## 2. 会議の検出とポップアップ（Zoom / Teams それぞれ）

モードは既定の「確認する」で行う。

- [ ] 会議アプリを起動しただけ（会議に入っていない状態）ではポップアップが出ない。
- [ ] Zoom の設定画面でマイクのテストをしてもポップアップが出ない。
- [ ] 会議に参加すると、数秒以内に画面の隅へ「〇〇 の会議を検出しました。録画しますか？」が出る。
      → 参加してから表示までの秒数：＿＿＿秒
- [ ] ポップアップは会議アプリのフォーカスを奪わない（入力中の文字が途切れない）。
- [ ] 何もしなければポップアップは消えない。メニューの状態表示が「会議を検出（確認待ち）」になる。
- [ ] 「今回はしない」を押すと消え、同じ会議の間は二度と出ない（5 分ほど待つ。ミュート/解除、カメラのオン/オフをしても出ない）。
- [ ] 会議を退出し、もう一度参加すると、またポップアップが出る。
- [ ] ポップアップに答えないまま会議を退出すると、約 10 秒でポップアップが消える。
- [ ] マイクをミュートしたまま参加した場合でも検出される。
      → 検出されない場合は診断ログを保存（ミュート時にアプリがマイクを開かない可能性。未検証事項）。
- [ ] ブラウザ版の会議では反応しない（対象外であることの確認）。

## 3. 録画の開始と録画対象（Zoom / Teams それぞれ）

- [ ] ポップアップで「録画する」を押すと、アイコンが赤丸に変わり、メニューが「録画中 00:00:xx」になる。
- [ ] （Windows 11）録画中に会議ウィンドウへ黄色い枠が**出ない**。
- [ ] （macOS）メニューバーに画面収録中のインジケータ（紫/オレンジのアイコン）が出る（OS の仕様）。

以下を録画しながら順に行い、あとで再生して確認する。

- [ ] 会議ウィンドウの上に別のアプリ（メモ帳、ブラウザなど）を重ねて 10 秒置く。
      → 再生：**重ねたアプリは映らず**、会議ウィンドウの中身だけが映っている。
- [ ] 録画中に OS の通知（メール、チャットなど）を表示させる。 → 再生：通知が映っていない。
- [ ] 会議ウィンドウを別のディスプレイ / 別のデスクトップ（Space・仮想デスクトップ）へ移動する。 → 再生：映像が続いている。
- [ ] 会議ウィンドウのサイズを変える（小さく → 大きく）。 → 再生：映像が途切れず、縦横比が保たれている（余白は黒）。
- [ ] 会議ウィンドウをフルスクリーンにして戻す。 → 再生：映像が続いている。
- [ ] 会議ウィンドウを 20 秒ほど最小化して戻す。 → 再生：最小化中は最後の映像で止まり、**音声は続いている**。戻した後は映像が再開する。
- [ ] 別アプリで音楽を鳴らす。 → 再生：**音楽は入っていない**。
- [ ] 相手に話してもらう／自分が話す。 → 再生：**相手の声と自分の声の両方**が聞こえ、口の動きと音がずれていない。
- [ ] 自分をミュートして 1 分ほど黙る。 → 録画が止まらない（メニューが「録画中」のまま）。再生：ミュート中の自分の声は……
      入っている / 入っていない（どちらだったか記録。OS のマイクを直接録るため入る想定）
- [ ] マウスカーソルが会議ウィンドウ上にあるとき、再生でカーソルが映る（`show_cursor = true` の既定）。

## 4. 画面共有への追従（Zoom / Teams それぞれ）

- [ ] **相手が**画面共有を開始 → 終了する。 → 再生：共有された画面が会議ウィンドウの中身として映っている。
- [ ] **自分が**画面共有を開始する（Zoom は会議ウィンドウが消えてツールバーと小さなビデオパネルになる）。
      → 録画が止まらない。
      - 既定：再生すると、共有中は**共有しているディスプレイ全体**が映る。音声に他のアプリの音は入らない。
        ログに「画面共有を検出：共有中の画面の録画に切り替え」が出る。
      - `record_shared_screen = false`：共有中は参加者ビデオのパネルが映り、共有している画面は映らない。
- [ ] 自分の画面共有を終了する。 → 数秒以内に会議ウィンドウの録画に戻る。ファイルは 1 つのまま。
- [ ] 画面共有をしたまま会議を退出する。 → 再生：退出後のデスクトップが映り続けない（数秒以内に映像が止まる）。
- [ ] 会議を退出すると録画が止まる（共有を一度でも行ったあとでも止まること）。
- [ ] （Teams）会議ウィンドウをコンパクト表示（ミニウィンドウ）にして戻す。 → 録画が続き、ファイルは 1 つ。
- [ ] 上記の最中に `meetrec.log` に「録画対象を張り替え」の行が出ている（診断ログの末尾でも確認可）。
      張り替わらない場合は、同じログの「録画中のウィンドウ」の行（共有中のウィンドウ構成）を報告する。

## 5. 音声デバイスの切替

- [ ] 録画中にイヤホン / ヘッドセット（Bluetooth と有線のどちらか）を接続し、会議アプリの入出力がそちらに切り替わる。
      → 再生：切替の前後どちらも相手の声・自分の声が入っている。切替の瞬間以外に途切れや音ずれがない。
- [ ] 録画中にイヤホンを外す。 → 同上。
- [ ] （Windows の Teams）PC を消音にしてから会議に参加する。 → 「PC の消音を外して音量を 0 にしました」と通知され、
      会議に入った瞬間も含めて、スピーカーから音は出ない。再生：**相手の声が入っている**。会議を出ると、消音と元の音量に戻る。
- [ ] （Windows の Teams）録画中に PC を消音にする。 → 2 秒ほどで同じ通知が出て、消音が外れ音量が 0 になる。再生：相手の声が続いている。
- [ ] （Windows の Teams）上の切り替えのあと、録画中に自分で音量を上げる。 → 会議を出ても、音量と消音はそのまま（戻さない）。
- [ ] （Windows の Zoom）PC を消音にして録画する。 → 通知は出ず、消音のまま。再生：相手の声が入っている。
- [ ] 10 分以上録画して、最後のほうで映像と音声がずれていない（手を叩く映像と音で確認）。

## 6. 自動終了と保存

- [ ] 会議を退出すると、約 10 秒以内に録画が止まり、アイコンが元に戻る。
- [ ] 「保存しました」の通知が出る。通知をクリックすると保存フォルダが開く。
  - macOS で OS の通知が使えないビルド（ad-hoc 署名）では、画面右上に MeetRec のパネルが出る。
    「フォルダを開く」で保存フォルダが開き、何もしなければ約 8 秒で消える。
- [ ] 保存先が「ダウンロード」フォルダになっている（macOS は初回にアクセスの確認が出る）。
- [ ] ファイル名が `YYYY-MM-DD_HHMM_Zoom.mp4`（Teams は会議名付き）になっている。
- [ ] 標準のプレイヤーでそのまま再生できる。
  - macOS：QuickTime Player、Finder のクイックルック（スペースキー）
  - Windows：メディア プレーヤー、「映画 & テレビ」
  - 共通：VLC、ブラウザ（Chrome / Edge へドラッグ＆ドロップ）
- [ ] シークバーで任意の位置へ移動できる。総時間が正しく表示される。
- [ ] 会議中にネットワークを 5 秒ほど切って再接続しても、ファイルが 2 つに分かれない。
- [ ] 会議アプリを（退出せずに）終了しても、録画が確定して通知が出る。

## 7. モードとメニュー

- [ ] ポップアップで「次回から確認せず録画」にチェックして「録画する」 → 次の会議から確認なしで録画が始まり、「録画を開始しました」と通知される。
      メニューの「会議を検出したとき」が「常に自動録画」になっている。
- [ ] 「常に自動録画」で録画中に「録画を停止」を選ぶ → 止まり、同じ会議の間は自動で再開しない。
- [ ] モード「オフ」では会議に入っても何も起きない。「今すぐ録画」で手動録画でき、会議終了で自動的に止まる。
- [ ] 会議に入っていない状態で「今すぐ録画」 → 会議アプリのウィンドウがあればそれを録画、なければ「ウィンドウが見つかりません」と通知。
- [ ] 「録画フォルダを開く」で保存先が開く。
- [ ] 「保存先を変更…」でフォルダを選ぶと、次の録画からそのフォルダに保存される。キャンセルでは何も変わらない。
- [ ] 録画中に会議アプリでミュートして話し、解除して話す。 → 再生：ミュート中の自分の声だけが入っていない（macOS）。
      `meetrec.log` に「会議アプリのミュート: ミュート中」「解除」が出る。
- [ ] 録画中に「自分の声を録る」をオフにして話し、オンに戻して話す。 → 再生：オフの間の自分の声だけが入っていない。
- [ ] 「ログイン時に起動」をオフにすると、次回ログイン時に起動しない。
- [ ] 「診断ログを保存」でファイルが作られ、フォルダが開く。

## 8. 異常系（録画を失わないこと）

それぞれ「2 分以上録画してから」実施し、**ファイルが再生でき、直前（数秒前）まで映像と音声が入っている**ことを確認する。

- [ ] **強制終了**：録画中に MeetRec を強制終了する。
  - macOS：アクティビティモニタで MeetRec を「強制終了」、または `killall -9 meetrec`
  - Windows：タスク マネージャーで MeetRec.exe を「タスクの終了」
  - [ ] 修復前のファイルがそのまま再生できる。
  - [ ] MeetRec を起動し直すと「前回正常に終了しなかった録画を修復しました」と通知され、総時間・シークが正常になる。
- [ ] **スリープ**：録画中にスリープ（ノート PC はふたを閉じる）→ 1 分後に復帰。
  - [ ] スリープ前までのファイルが再生できる。
  - [ ] 会議が続いていれば、復帰後に確認なしで新しいファイルへ録画が再開される。
- [ ] **ログアウト / シャットダウン**：録画中にログアウトする。 → 再ログイン後、ファイルが再生できる。
- [ ] **MeetRec の終了**：録画中にメニューから終了する。 → ファイルが再生できる。
- [ ] **電源断**（可能なら）：録画中に電源ボタン長押し。 → 再起動後、修復通知が出て再生できる。
- [ ] **ディスク残量不足**：`config.toml` の `min_free_mb` を現在の空き容量より大きい値（例：`99999999`）にして再起動し、会議に入る。
      → 「ディスクの空きが足りないため録画を開始できません」と通知される。
      → 録画中に同様の状態を作れる場合（大きなファイルをコピーして空きを減らす）：「空きが少ないため録画を停止しました」と通知され、ファイルは再生できる。
- [ ] **キャプチャ保護**（該当する会議がある場合）：映像が録れない会議では「音声のみ録音しています」と通知され、音声だけのファイルができる。

## 9. リソース計測（1 時間録画）

目標：待機中 メモリ 30MB 以下・CPU 平均 0.1% 以下 ／ 録画中 メモリ 150MB 以下で増え続けない・CPU 1 コアの 10% 以下。

### MeetRec の自己計測を使う方法（推奨）

1. MeetRec を起動して 10 分以上放置する（待機中の計測）。
2. 会議を 1 時間録画する（相手の映像が動いている状態と、資料共有などの静止状態の両方を含める）。
3. 録画中のまま「診断ログを保存」を実行する（録画終了時にも同じ内容が `meetrec.log` に出力される）。
4. 診断ログの「自己計測」欄を記録する。

```
待機中: メモリ 現在 __MB / 最大 __MB / 初回 __MB、CPU 平均 __% / 最大 __%
録画中: メモリ 現在 __MB / 最大 __MB / 初回 __MB、CPU 平均 __% / 最大 __%
```

- [ ] 待機中：メモリ最大 30MB 以下、CPU 平均 0.1% 以下
- [ ] 録画中：メモリ最大 150MB 以下、CPU 平均 10% 以下
- [ ] 録画中：「初回」と「現在」の差が小さい（増え続けていない）。`meetrec.log` の `計測[録画中]` 行（30 秒ごと）を
      最初・30 分・60 分で見比べ、右肩上がりになっていないこと。

### OS のツールで裏取りする方法

- macOS：アクティビティモニタ → MeetRec の「メモリ」「% CPU」。または
  `top -pid $(pgrep meetrec) -stats pid,cpu,mem -l 0 -s 60` を 1 時間流して記録。
  「エネルギー」タブで GPU 使用の有無も確認（ハードウェアエンコードなら CPU は低い）。
- Windows：タスク マネージャー → 詳細 → MeetRec.exe の「CPU」「メモリ (アクティブなプライベート ワーキング セット)」。
  または PowerShell：
  ```powershell
  while ($true) { Get-Process MeetRec | Select-Object CPU, @{n='MB';e={[int]($_.PrivateMemorySize64/1MB)}}; Start-Sleep 60 }
  ```
  （`CPU` は累積秒。60 秒間の増分 ÷ 60 × 100 が 1 コア比の %）
- [ ] 録画中、会議アプリの動作（映像のカクつき、音切れ）に影響がない。
- [ ] `meetrec.log` に「ソフトウェアエンコード」へのフォールバックを示す行が**出ていない**（ハードウェアエンコーダが使われている）。
- [ ] 1 時間の録画ファイルのサイズ：＿＿＿MB（目安 700MB 以下。静止画面が多ければもっと小さい）
- [ ] バイナリサイズ：＿＿＿MB（目標 20MB 以下。CI のログにも出力されます）

## 10. 報告のしかた

- どの項目が NG だったか（OS、Zoom/Teams、UI 言語）
- その状態で保存した診断ログ（`diagnostics/MeetRec-diagnostics-*.txt`）
- 録画の不具合の場合は、可能なら数秒の録画ファイルか、`ffprobe -show_streams ファイル` の出力
